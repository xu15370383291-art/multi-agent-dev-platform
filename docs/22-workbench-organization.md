# 工作台信息分类整理

用户要求：项目详情内容过多，需要按用途分类并标注。这是现有工作台的可用性调整，不改变M2/M4/M5的阶段门槛或宣布正式M4完成。

实施映射：

| 要求 | 模块 | 验证 |
| --- | --- | --- |
| 按用途分类、说明作用 | main.tsx的五类导航和说明 | 桌面/手机切换、项目切换、空状态 |
| 已交付优先预览和下载 | 成果概览；重新运行放入独立折叠操作 | 交付链接、无意外POST、重运行合同 |
| 保留审批与全部证据 | 需求审批、开发协作、质量验收分区 | 版本化审批请求、构建日志/原报告可展开 |
| 长清单按需展开 | 验收摘要、文档正文、事件原始数据 | 明细可查看、失败不写成通过、键盘可访问 |
| 重运行后旧交付仍可查 | main.tsx运行记录选择、按所选run读取证据 | 新轮执行时查看旧ZIP，不暴露旧轮取消/重启动作；真实历史修复运行切换 |

沿用现有深蓝/浅蓝工作台风格；标题用微软雅黑、正文Segoe UI/微软雅黑、版本数据Consolas。以带用途说明的分类导航代替单页堆叠，完成成果作为默认入口；待审批事项在概览提供直接入口。按钮与分类均使用真实状态，未交付时明确说明尚无成果。隐藏内容仍保留原始证据，审批、预算、模型配置、隔离与后端流程不变。

## 实施结果与验证

- 已实现五个独立分类和用途说明，默认显示成果概览，待审批提示可直接跳转。未审批正文展开，已生成文档正文收起；原始结构化数据仍可核对。任务/质量/执行记录各归其类，事件有中文名称和可展开原始回执，支持所选运行/整个项目两种范围。
- 交付验收显示总数、通过数和其他结果数，明细保留AC编号；不把unknown或失败统计为通过。预览/ZIP作为主要操作。终态的重新运行入口独立折叠，说明原需求重新分析、重新审批及额度消耗，原幂等请求合同保留。
- 真实检查发现：源码修复项目已有更新的取消轮次，原界面只加载最新run，导致历史成功交付不易找到。新增“运行记录”，按所选run加载候选/任务/报告/ZIP；查看历史有提示，最新运行仍活跃时，不从历史页面提供取消/再次启动操作。切换项目清理临时输入与旧证据，切换轮次显示加载状态，重复选择当前轮次不清空已有数据；轮询不重置当前分类和展开状态。
- `npm run build`通过TypeScript和Vite构建。
- `npx --no-install playwright test --reporter=list,junit`：最终26项桌面/手机测试通过；JUnit见`.local/workbench-organization-tests.xml`。新增测试明确使用HTTP fixture，覆盖分类与证据展开、键盘操作、轮询保留选择、空状态、项目切换、原版本审批POST、活跃新轮下查看历史交付及无意外写请求；原质量/协作/候选/模型配置测试适配分类入口后通过。真实控制面加载检查也保留。
- `node scripts/organization-live.mjs`：4组原真实模型交付×1440/390宽度，共8个真实HTTP/Edge上下文通过。实际切换全部分类，核对交付QA/Reviewer ID、下载ZIP摘要、打开正确预览，事件原始数据默认隐藏且可展开，无页面错误/横向溢出/写请求。特别切回旧修复成功轮次验证交付仍可用。报告与截图：`.local/workbench-organization/live-results.json`及同目录PNG。
- 开发中首轮真实检查按最新run假设寻找修复交付失败，由此补齐历史入口；新增选择器初版用嵌套label文本定位时包含option文字，明确补充`aria-label`后，桌面/手机历史选择测试和真实检查均通过。重复选择当前轮次时也避免无意义清空；最终结果以完整重跑为准。

本次仅调整前端信息组织及读取既有轮次，未新增模型调用、未改后台/审批/预算/数据库/交付门槛。后端全量未重跑，原C6报告保留为当时源码的历史证据，不把它当作本次变更后的全量重验。当前工作台复验使用上述新脚本；早期里程碑浏览器脚本的单页定位属于旧UI，不应直接当作新分类界面的验证。完整M2、正式M4/SSE与M5仍未完成。
