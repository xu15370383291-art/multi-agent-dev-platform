## 已实施

- `auto_correction.py` 使用持久 WorkItem 协调，不依赖前端定时器；Supervisor 沿用原角色模型快照，通过结构化结果回执及原调用计量提出修正。控制端不执行模型命令；实际修改仍由原 Developer 经 Tool Gateway 执行。
- 纠错前核验批准版本、已结束工具、快照摘要、进程停止状态、调用策略和取消/人工暂停；修正计划必须覆盖全部目标、引用其真实工具记录、不能重复已有原命令。
- 应用后沿用免费 `process_check` 和版本化 `request_resume`，创建原执行的子尝试，保留源码快照、已消耗调用/工具/活动时间、原失败与审批，不从需求重新开始。
- 同一已验证成果的处理指纹不因改命令文字、换模型、换尝试 ID 或增加调用次数变化；没有新有效成果或新平台校验诊断时不重复自动规划。有新验证成果可以再次纠错，无累计调用总额限制。新工具参数诊断只采集实际未执行的拒绝记录、工具官方字段和错误类型；更换值、ID或多余字段名称不算新诊断。
- 暂时性已确认模型故障允许检查后受控恢复；未确认请求/工具、失租、人工暂停/取消、待审批及终态不自动重放。
- 检查证据/代码提交检查被拒绝后，原声明和失败计数保留于原会话；经有依据的自动新策略授权后，子会话重新生成结果，不复用被拒绝的完成声明。全局调用、工具与活动时间不重置。
- 工作台简单显示自动分析、检查、继续或需要用户决定，技术数据仍在高级详情。不能自行改已批准需求或自动纠正错误验收断言；原质量闭环保持。
