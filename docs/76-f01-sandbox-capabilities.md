# F01：QA沙箱接口与实际能力一致性修复

2026-10-27，承接docs/75的B1/F01。用户授权修复平台F01；真实项目继续保持暂停，不重试未知请求、不调用收费模型、不修改正式业务源码或98条原测试。本记录只关闭F01相应接口与定向验证范围，不宣称F02—F09或完整自主交付通过。

## 根因与范围

1. **返回数组的能力被平台破坏**：m11沙箱把数组/普通对象整体JSON克隆，m14继承了该实现。Playwright的`Locator.all()`返回定位器数组，跨沙箱时其中对象的方法丢失。因此`items[0].locator is not a function`至少有已复现的平台根因，不能只归咎于QA写错接口，也不能通过禁止合法的`Locator.all()`掩盖问题。
2. **宿主与浏览器作用域合同不完整**：QA宿主是受限VM，不提供Node的URL全局。原语法预检允许`new URL(...)`进入实际执行才报错。浏览器回调中的URL可用；局部自定义同名变量和合法能力探测不能被一律禁用。
3. **修订校验与能力合同冲突**：镜像预检允许合法浏览器URL解析，但原步骤修订校验器把原URL表达式等价移入浏览器判成`quality_procedure_browser_result_forged`，导致合法修订反复被拒。此问题在本次补测中实际复现，不能只修生成提示。

## 关闭边界

静态预检只诊断能够确定的接口用法，不证明整个脚本功能正确。运行时才能确定的别名、反射、应用对象能力或浏览器故障仍保留实际错误，不伪造结果或直接归因源码；完整归因属于F04，业务语义与前置步骤属于F02/F03。

两个真实项目类型链路中的模型是显式协议夹具，只验证平台如何处理合法/错误的模型输出，不能作为百炼生成正确测试的证明。当前正式QA仍88/98通过、终审仅15项有效片段，未知结果与暂停保持，旧失败和交付包不变。
