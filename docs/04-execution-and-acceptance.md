## 1. 执行分层

平台控制端负责创建工作区、安排容器和执行服务；Agent 通过 Tool Gateway 使用受控能力。项目代码和 Agent 可执行命令不得获得 Docker Socket 或宿主机控制权限。

文件路径应按实际解析结果验证边界，包括父目录、符号链接和写入目标。原始字符串前缀匹配不足以证明路径安全。命令在项目执行环境中运行，不能仅在宿主机切换 cwd 来模拟隔离。

容器可以拥有运行时、系统库和包管理工具；“项目外禁止访问”指项目外的宿主机和其他项目文件，不是禁止读取容器运行所需的系统文件。

容器镜像、网络访问、包下载、代理及资源限制由平台配置。网络策略需支持正常开发并防止访问宿主机管理服务，具体规则在 D12 确定，不用提示词替代执行边界。

## 2. 建议的项目布局

```text
project_workspace/
├── repo/              # 主仓库与集成分支
├── worktrees/         # 任务工作目录
├── artifacts/         # 候选、交付包及 manifest
├── reports/           # QA、审查与汇总报告
├── executions/        # 工具日志、结果和执行元数据
└── tmp/               # 有生命周期的临时文件
```

具体路径名可调整。worktree 必须由 Git 创建；主仓库、worktree 的共同 Git 元数据必须在授权范围内可访问，容器内路径映射须保持有效。并行 Agent 只修改自己的任务目录；集成目录由统一集成流程写入。

## 3. Git 开发与集成

1. 从已知集成 SHA 为任务创建 worktree 和分支，登记基线与执行身份。
2. Agent 修改代码、执行局部检查并提交成果，系统核对实际 Diff 和提交。
3. 任务成果进入集成队列；同一项目同一时刻只有一个集成写入者。
4. 在最新集成基线上应用任务变更，检查合并结果与必要验证。
5. 冲突或检查失败产生明确的处理任务；不得静默选择任意一方代码。
6. 成功后登记目标 SHA 和 integration_status=merged，重新评估下游依赖。
7. 所需任务全部集成后，创建不可变 Candidate 记录。

Candidate 至少包含 candidate_id、run_id、plan_version、批准文档版本、commit_sha、依赖锁文件摘要、构建环境标识。依赖能否安装及构建结果仍须真实验证，元数据本身不能证明可复现。

## 4. 并行执行与资源

worktree 隔离文件变更，不隔离端口、数据库或进程。平台需为每个活动执行分配命令进程、临时目录、预览地址及测试数据命名空间；无法隔离的资源串行使用。

同项目并发上限和系统总上限分别控制。运行长服务必须记录 PID/容器执行单元与所属任务，任务结束、取消或过期后按生命周期清理。

并行任务须明确接口、预期文件范围和共同配置文件的归属；同一关键配置的修改优先通过独立集成任务协调，不能只因 DAG 没有依赖就判定适合并行。

## 5. 固定候选版本的 QA 与审查

- QA 和 Reviewer 均从 Candidate.commit_sha 读取，不跟随移动分支。
- QA 在独立验收目录构建运行；报告、截图和临时文件写到专用产物目录。
- QA 新增测试脚本需保存为版本化测试资产，报告关联候选 SHA、测试资产版本和环境标识。
- Reviewer 默认只读，报告关联候选 SHA、比较基线、问题位置和证据。
- 任一修改生成新候选，旧报告只对旧候选有效。
- V1 建议每个新候选执行完整的基础构建、批准验收用例和审查；暂不依赖复杂的增量证据复用算法。

## 6. 审查问题等级建议

| 等级 | 示例 | 默认建议 |
| --- | --- | --- |
| critical | 明确敏感信息暴露、严重越界或数据破坏风险 | 阻断 |
| major | 关键功能错误、明确违反批准架构、无法运行 | 阻断 |
| minor | 非关键缺陷、局部维护性问题 | 报告并按验收约束决定 |
| suggestion | 风格偏好、可选优化 | 不单独阻断 |

问题须包含可定位的证据和影响。Reviewer 的等级需要结构校验；争议问题可由 Supervisor 请求复核或人工决定，不能靠改写等级静默消除。最终等级和豁免机制仍需确认。

## 7. 确定性交付门槛

系统代码逐项检查：

1. 批准的 PRD、架构、当前计划和候选版本关系有效。
2. 必需任务成功，所需代码已完成集成。
3. 必需验收标准全部有适用当前候选的通过证据。
4. 构建及必需测试完成；工具退出结果和报告均可追溯。
5. QA 与 Reviewer 针对同一候选，且不存在未解决的阻断问题。
6. 交付文件实际存在，manifest 引用和内容摘要可核对。
7. 已知问题和未实现范围已披露；预览属于约定交付内容时须实际可用。

Supervisor 可以汇总并建议交付，但不能把 not_verified 改成 passed。必需检查未运行、执行结果未知、报告版本不符时，门槛不通过。任何人工豁免都必须显式记录，且不得等同于该项测试通过。

## 8. 交付清单建议

交付 manifest 包含：项目及运行 ID、需求/文档/计划版本、候选 SHA、源码包与摘要、运行说明、依赖及环境信息、验收覆盖表、QA 和 Reviewer 报告、已知问题、预览地址与有效期。

交付 ZIP 采用明确包含规则，排除密钥、.env 私密值、临时目录、不必要的依赖目录及其他项目内容。预览进程与任务进程分别管理，交付后保留多久由 D10、D12 决定。
