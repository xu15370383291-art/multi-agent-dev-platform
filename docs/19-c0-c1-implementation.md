工程选择：本阶段活动开发额度固定为1，以数据库运行锁串行化派发准入；数据库记录可扩展到多任务，但单任务工作流明确拒绝多任务计划执行。每个新执行先预留一次模型调用，实际调用原子消费预留，后续调用从未预留余量扣除；任何调用均不得占用其他执行预留。预留是原预算内分配，不增加30次总额。失败/未知预留保留待核对，已知终态释放未消费额度。

旧M1执行不强制回填或更改批准文档/ZIP；新增外键可空代表历史。恢复既有执行时校验其原批准基线；新执行必须建立版本化计划。当前不开放任意新计划激活API，后续C2实现重规划与活动执行切换规则。

真实Web示例拟采用本地任务管理：新增、完成、筛选、删除及刷新保存/存储异常、中文手机布局。示例最终范围以真实Product/Architect产出和版本审批为准，不人工替代模型写业务代码。验收代理只在既有授权内审阅审批，不改原M1交付。

- `model_reservations` 在运行锁内预留和消费；所有角色调用计费入口扣除其他执行已占额度，Developer 消费自身预留。已知终态释放剩余额度，unknown 不盲目释放后重试。C0/C1 每运行只准入一个开发执行；真正多任务调度、总资源准入和并行执行仍在 C2/C3。
- 增量迁移 `657871c00e05` 和 `17c233a39f21` 建立计划、任务、预留与外键。实际随机 schema 从 M1 head 升级，核对历史执行、30次调用、1483活动秒保留；计划存在时拒绝会丢失历史的降级。`alembic check` 无新操作。
