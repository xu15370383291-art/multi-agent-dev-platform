# 模型配置、选择与切换

M2暂停后切换的实施设计见 docs/26 第9节和 docs/27 的 M2-44—47；当前为设计，运行级切换尚未据此上线。原配置与活动执行快照规则保持。

状态：产品方向已确认，具体实现方案为规划建议。日期：2026-10-19。

## 1. 用户已确认的需求

平台提供模型选择功能，用户自行填写 API Key、Base URL，选择模型类型/型号，并能随时切换。不固定某个模型或供应商。首版个人使用，在当前 Windows 电脑运行。

Agent 的角色、任务、工具和工作流由平台定义，模型是其可配置的推理能力。更换模型不改变角色职责、工作区边界、审批、验收门槛或运行总预算。

## 2. 配置界面建议

设置 → 模型配置，包含配置列表、创建/编辑表单、连接测试、能力结果、默认模型和 Agent 分配。

| 字段 | 说明 |
| --- | --- |
| 配置名称 | 用户可读名称，可保存多份配置 |
| 接口协议/适配类型 | 用于选择 LangChain 适配器，不是模型能力标签 |
| Base URL | 用户指定的服务根地址；适配器规定是否包含版本前缀 |
| API Key | 密码输入，保存后仅返回是否配置与掩码 |
| 模型 ID | 支持手动输入；服务支持时也可获取列表后选择 |
| 调用参数 | 仅展示该适配器支持的超时、输出上限及可选参数 |
| 能力状态 | 普通对话、工具调用、结构化结果、流式输出等，显示已验证/未验证/不可用 |

“模型类型”在界面中拆成接口协议和模型 ID，避免把供应商、模型名称、代码能力混为一项。思考模式和温度等选项按实际能力展示，不能向所有模型发送同一组参数。

已实现的百炼 Qwen、官方 DeepSeek 思考选项及验收边界见 [模型兼容层整体修正](13-model-adapter-contracts.md)：默认保留供应商行为，可显式开启/关闭；模式随配置版本和角色分配生效，修改后重新检测，不为兼容工具调用自动关闭。供应商策略和前端显示以同一后端注册表为准，适配版本或请求限额改变后旧检测失效。

## 3. 接入范围建议

V1 优先提供自定义 Base URL 的 OpenAI 兼容 Chat Completions 适配器，同时保留 provider adapter 接口。原生供应商协议按实际需求增加，不能宣称输入任意 URL 就支持所有模型 API。

普通对话兼容不代表工具调用、结构化输出或供应商扩展字段也兼容。具体功能按配置的端点与模型验证；某个适配器支持某项功能，不等于它连接的所有模型都支持。

使用非标准功能时应评估供应商专用适配器，不将未保留的响应字段当成已支持。首个实际供应商现为百炼，已加入保留 reasoning_content 的兼容适配；非兼容原生协议仍未实现。

## 4. 模型选择与角色分配建议

支持一份默认配置供七类角色共同使用，也支持给具体角色指定不同配置。

C1已验证Web Developer按web_app类型解析自己的绑定并在执行开始固定profile revision，调用/事件记录使用web_developer，不再借用game_developer的配置或名称；原Game路径回归通过。不同角色的下一次新执行可解析最新绑定，活动Developer工具链不偷换配置；当前任务中途暂停切换仍属M2，未因Web接入而宣称完成。证据见docs/19。

C2—C5中，批次准入时每个执行固定自己的profile revision，修改绑定/配置只影响后续新执行；已有批次不偷换模型。执行、全部角色调用及质量报告快照可在工作台查询。Developer取得有来源的受限基线源码上下文，避免逐文件多轮读取耗尽调用预算；不会因此删需求、关闭思考或重置调用/工具/时间额度。真实源码修复12/30次通过；另一四任务项目30/30停止，额度变更待明确确认，详见docs/20。

建议优先级：项目内角色设置 → 项目默认 → 全局角色设置 → 全局默认。界面始终显示当前有效来源，避免用户修改全局配置后误以为项目覆盖也被修改。

空配置允许完成平台初始化和文档浏览；真实工作流启动前，需检查所需角色是否都有可用模型。首次联调不要求把真实 Key 写入源码或聊天。

## 5. 随时切换的生效规则建议

用户可随时修改选择；界面显示“已生效”或“等待当前执行结束”，不静默改变正在执行的请求。

- 当前模型请求和工具调用链保持其配置快照，避免请求与工具结果跨协议串接。
- 默认在下一个任务执行尝试启动时应用最新的有效选择；一个运行可以包含不同模型的执行记录。
- 希望当前长任务也切换时，提供“暂停后切换”：停止新增调用，等待或终止活动请求，核对工具副作用，保存已有工作，再创建关联的继续执行记录。
- 继续执行从任务目标、代码、证据和摘要重新组装上下文，不直接把供应商私有消息格式传给新模型。
- 无法确认旧工具结果时进入恢复处理，不能切换后盲目重做。
- 每次实际调用记录非敏感配置版本与模型 ID；更换模型不重置任务尝试次数、修复轮数和总预算。
- 失败后默认报告错误并允许用户换模型，不自动把项目内容发送给另一供应商。

更新 Key 或 Base URL 产生配置新版本。禁用配置后不启动新调用；在用版本保留审计引用，密钥撤销和删除则以用户显式操作为准，旧执行不能依赖已撤销密钥继续运行。

## 6. 连接与能力验证

测试分层执行：参数和 URL 校验 → 最小对话 → 无副作用的工具调用及结果回传 → 结构化结果校验。流式输出按需要独立测试。

工具测试使用固定的纯计算工具，不访问项目文件。结构化结果可以通过原生 schema、工具策略或经校验的结构化文本适配，但必须记录实际策略及验证结果。

测试由用户主动触发，使用固定测试内容，不发送业务项目上下文。界面显示测试会发起实际 API 请求；模型列表不存在或被禁用时允许手动输入，不把列表失败当成模型不可调用。

开发 Agent 必须通过工具调用闭环验证。Supervisor、Product、Architect 和 Reviewer 必须能产出可校验结构；QA 是否必须调用工具取决于其执行设计。未验证的关键能力不能显示为通过，失败或能力不足时说明哪些角色不能分配。

## 7. 数据与密钥建议

- ModelProfile：配置 ID、名称、协议、Base URL、模型 ID、参数、revision、启用状态、credential_ref。
- ModelBinding：全局/项目范围、角色或默认项、profile_id。
- CapabilityCheck：配置版本、检查类型、时间、结果和脱敏错误。
- InvocationRecord：执行 ID、profile_revision、模型 ID、请求状态、耗时、用量、估算费用和错误类别。
- SwitchRequest：作用范围、旧/新配置版本、请求与实际生效时间、关联执行和处理结果。

Key 存在平台控制端的独立秘密存储中，业务表只保留引用；Windows 本机优先评估系统凭据保护。API/Worker 如何共享受保护凭据需随部署方案确定，不先写死为某种容器内文件。

Key 不进入 LangGraph State、Agent 消息、业务项目容器、Git、交付包或普通日志。管理界面保存后不回传明文；运行时只由模型接入模块取用。

URL 不接受用户信息段或查询参数中的凭据；跨域重定向不转发认证头。更新 Base URL 时明确新目标并重新验证，不能因旧地址通过测试就信任新地址。允许用户配置本地模型服务，但它与 Agent 的文件/命令权限分开，模型不能自行修改目标地址。

## 8. 模块与接口草案

模块：模型配置服务、凭据存储、适配器注册、模型实例工厂、能力检查、配置解析与快照、调用计量、切换协调。

接口候选：

- GET/POST /api/v1/model-profiles：列出脱敏配置、创建配置。
- GET/PATCH /api/v1/model-profiles/{id}：读取脱敏配置、修订配置。
- POST /api/v1/model-profiles/{id}/validate：连接与能力测试。
- POST /api/v1/model-profiles/{id}/models：显式查询可用模型列表。
- GET/PUT /api/v1/model-bindings：查询及更新全局/项目选择。
- POST /api/v1/runs/{id}/model-switches：当前运行请求暂停后切换。

接口路径与版本冲突处理在正式 API 合约中确定；更新配置需做并发版本校验。模型选择不能由 Agent 自行调用管理接口更改。

## 9. 实施与验收

M0 明确首个适配范围、凭据方案和切换语义。

M1 在简易页面提供配置、测试、默认选择及执行快照，完成一次真实 Agent 工具调用。不得只依靠环境变量硬编码模型来认定用户配置功能完成。

M2 补齐暂停后切换、调用取消与结果核对；M3 验证并行任务的配置快照及角色分配；M4 完善正式设置页。

验收用例：保存两份配置并切换；改模型后新执行应用正确版本；活动执行的选择可追踪；不支持工具调用的模型不能用于开发；切换不丢失代码或重复未知工具副作用；Key 不出现在返回值、日志、检查点和交付物；无模型列表时仍可手动配置；供应商不可用时给出可处理错误。
