2026-10-23补充：用户已批准docs/46质量分流扩展。可证明的最小测试调用修订和漏测补齐允许自动处理，经独立审查与新候选完整执行；原断言不能删除或放宽，错误业务断言语义仍按人工核对规则。具体实施和真实状态见docs/47。

2026-10-22。用户明确授权规划并补齐：出错后根据原需求自纠错、修复并继续，简单说明原因，避免可修复问题长期阻塞。本决定补充此前只允许人工登记新策略的规则；原审批、未知副作用核验、隔离、取消和质量门槛不变。

## 执行流程

识别暂停原因 → 核验原操作已结束且结果明确 → 持久登记自动处理工作 → 主管读取原需求、批准方案、任务及实际失败证据 → 提出不同且可执行的处理办法 → 保留历史登记策略 → 免费恢复检查 → 检查通过后创建原任务的新执行尝试 → 开发实际修正及验证 → 原 QA、独立审查与交付流程。

工具失败仍首先由开发 Agent 在原上下文中修正；自动纠错协调补上触发停滞/完成证据拒绝/可确认模型暂时故障之后的恢复闭环，不改写已完成工具结果，也不从原需求重做整个项目。

| 要求 | 模块 | 验收 |
| --- | --- | --- |
| 自动发现可处理暂停，重启后持久推进 | auto_correction + Worker + WorkItem | 任务只登记一次、并发领取、重启、失败中断不盲重放 |
| 真模型基于实际证据规划修正 | 原 supervisor 模型配置/计量/结构合同 | 真实模型项目；测试明确使用夹具，计划必须引用已有结果 |
| 新策略需要实际不同且有依据 | 持久纠错指纹、原 progress_strategy、完整历史 | 重复策略拒绝；同一已验证成果上无进展不得无限换命令 |
| 正常任务不设总次数或总时长上限 | 原 v2 策略继续 | 有新可验证成果可再次纠错；不能靠时间、换模型/ID或改日志获取重试资格 |
| 验证后继续原执行，不绕过门槛 | 原 process_check/request_resume/continuation | 原审批/SHA/快照、未知回执、取消/租约及新尝试关联不变 |
| 暂时模型故障可受控恢复 | 确认失败的模型请求、现有检查点与恢复 | 不将 running/unknown 当失败，不无限重发同一失败请求 |
| 用户看懂原因及处理进度 | diagnostics/PauseNotice/ReliabilityPanel | 简单显示“正在分析/修复/检查/继续”；高级信息折叠 |
| 不能自行处理时明确缺什么 | 分类诊断、固定安全说明 | 需求变更/审批/权限凭据/未知结果保留人工入口；不让模型自述覆盖平台证据 |

## 自动化边界

每个“已批准目标 + 任务职责范围 + 最近已验证成果/新的平台校验诊断”的纠错机会持久登记；同一成果上自动修正未形成新的有效进展时，不能再靠换一种说法无限调用。新的参数诊断仅取平台实际拒绝且未执行的工具、官方字段和错误类型；相同类型换值、换工具ID、发明不同多余字段或改日志不算新信息。原重复/状态循环/停滞检测和调用计数保留。此为无进展防空转，不是累计调用额度。

人工暂停、取消、待审批、终态不自动恢复。未知工具/集成/构建/QA/模型结果、快照损坏、环境未确认停止、凭据不足、需改变已批准要求时不能自动重放或自动批准。已存在的 QA→源码修复→新候选→QA/Reviewer 保持；错误测试断言仍按原人工核对协议，不自动降级标准。

验证顺序：隔离专项 → 恢复/并行/取消等回归 → 桌面手机 UI → 正式服务更新 → 仅续用推方块这一实际项目做真实模型验收，不额外创建多个收费项目。完整完成与剩余边界在实施报告如实记录。

## 2026-10-23 QA长回复故障的实施细化

真实项目显示，整套测试一次生成容易超出既有数组合同、产生超长回复或模型等待超时。v2正常进展模式的首次QA改为按批准AC逐项生成：每项一个完整case，script保留该AC全部子场景与断言；全部case合并后仍须语法/引用/覆盖检查、同SHA真实执行和独立审查。不是逐项宣称测试通过，不删除边界、不放宽断言，不调整既有单次资产合同。fixed历史模式保持原调用方式，源码修复后的冻结测试及人工审阅修订规则不变。

每项结果使用固定候选、批准文档、目标AC、模型版本、结构合同和完整上下文绑定的持久结构回执；中断后复用已完成项，仅生成未完成项。报告单独记录生成进度，明确executed=false，不伪装成已执行QA证据。新的有效分项回执可以提供新的恢复依据；同一失败项没有新有效结果时仍不得无限重试。只改变文字、调用次数或尝试ID仍不能获得新机会。

纯生成故障的自动识别覆盖确认失败的格式错误和暂时模型故障，必须仍然证明只有已成功的源码检查、没有测试执行/其他不明操作、模型角色和固定配置对应，并核对操作身份/参数/实际回执/快照。不能仅凭错误名称把unknown改成失败；免费对账及版本化续接步骤保留。

2026-10-23补充授权与实现：只有开发新增、未成为正式验收基线且被原需求/原QA明确证明错误的自检，可保留旧脚本/失败并经独立审查后修正；原有正式测试和用户验收仍冻结。恢复合同携带当前可信源码、原基线、真实差异及non_goals，旧行动建议不与新建议冲突发送。见[docs/48](48-derived-selfcheck-correction-policy.md)，真实验收进度见docs/47。
