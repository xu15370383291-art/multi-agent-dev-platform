## 本轮发现与修复

- QA 复用工具模块的顶层入口误执行：改为 `__main__` 入口，导入不再消费请求。
- Chromium 私有目录导致 root（已丢弃 capabilities）无法归档：导出改用任务 UID，与文件归属一致；清理容忍已退出进程竞态，不放宽容器权限。
- 浏览器环境下线程式静态服务器资源争用：改用单线程 HTTPServer，启动就绪检查；保留 CPU/内存/PID/断网边界。
- 静态 HTML 候选中的上次 dist 导致独立 QA 重建被当作脏源码：容器内清理生成目录后从固定 Git 提交重建。
- 仅凭脚本含 assert 字样不足以证明执行断言：记录实际断言调用次数，无执行断言的用例不能通过。
- 初次真实百炼请求耗尽 4096 输出且全部为思考，随后增加总输出仍有超时：增加显式配置限额，不关闭思考、不隐式换供应商。正式配置使用 16384 输出、180 秒、思考预算 2048，并重新验证三项能力。
- 模型把 criteria 数组编码为字符串：拒绝强制解析；明确 schema 和提示，纯结果文档最多一次同模型同 schema 的计量纠正，保留失败记录。
- 审阅正式 PRD 发现“有效移动后数量总是加一”错误：工作台要求修改为 n−合并次数+1，审批修订版；架构提出不存在的 Vite 内置测试、断网 npm 安装和 TS 导入问题，要求版本化修订，不批准已知错误。
- 真实开发暴露工具定义只有名称、通用错误反馈与当前工具无关：补充各工具职责、前置条件、参数示例及当前工具完整 schema；Git 明确 commit 自动暂存、message 仅短标题，参数拒绝不执行、不计为成功。依赖符号链接须用 `node_modules` 忽略而非仅 `node_modules/`。失败运行 `406448d6-6122-490d-819b-c8f8f26597ff` 单测18项与构建通过，但连续错误 Git 参数触及24步开发上限（运行29/30调用），保持未交付并取消；未扩预算或人工补写完成记录。修复后单独重新执行正式验收，保留失败历史。
- 正式运行在成功提交后因检查引用 ID 不匹配被阻止：工具消息补真实调用回执，结果引用最多一次计量纠正。补上同一批准基线/原预算的狭窄核对恢复，包含父图暂停终点的检查点重入校验；未知、超时、活动容器和耗尽预算仍拒绝。实际从20/30继续至21/30，34项游戏单测和构建再次通过，同一提交未被人工替换；27项定向测试通过（62.93秒），包含真实 PostgresSaver、Docker、两次引用拒绝后恢复及固定候选质量/交付。
- 第一轮 QA 暴露未定义 browser 和 evaluate 多参数调用；第二轮模型补丁包含 TypeScript 的 as any，四用例未执行。增加明确的纯 JavaScript 合同和容器内纯编译预检，语法错误最多一次同模型、单独计量纠正，不执行脚本、不做静默转换。原失败报告全部保留。
- 第三轮原资产仅 AC-004 超时。加阶段定位和资源采样后发现新上下文 newPage 被128进程/线程上限阻塞，CPU配额和亲和性本身不能消除软件3D线程。收敛 Chromium 软件3D/V8/栅格线程，保持真实 DOM/CSS 绘制、独立存储上下文、CPU/内存/PID与7秒用例上限；超时清理该用例创建的全部上下文。原七脚本未改一字即可完成115条断言，另增加三个隔离上下文连续读写/关闭的真实 Docker 回归。
- 增加明确触发的原资产环境重验：同候选、同原资产hash、新固定镜像、新QA报告和新Reviewer调用；原调用预算只需剩余一次用于审查，不重新生成QA资产、不修改源码或审批。请求/Worker/工具均核对镜像和历史报告ID，未知工具、产品断言失败、源码阻断、同镜像、交付后、预算不足均拒绝。它不是通用未知恢复或源码自动修复。
- 独立交付检查脚本首次运行发现下载URL缺少API前缀，修正脚本后重新完整核对40个文件摘要；此错误仅在验收辅助脚本，不修改已交付ZIP。真实工作台下载也另行核对相同ZIP摘要。
- 最终门槛检查补齐 Reviewer 与 QA 验证环境完全一致的显式比较；新增错镜像拒绝路径，原正式候选用最新 gate 再核对仍通过，报告/源码/ZIP均未改写。
