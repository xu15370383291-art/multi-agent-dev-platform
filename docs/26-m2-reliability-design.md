## 1. 目标与范围

恢复的对象是同一运行里的具体动作，不是从需求重新生成整个项目。运行位置由 PostgresSaver 提供，副作用由业务账本、受控执行回执和内容摘要共同核对。恢复后仍经过原来的依赖、预算、审批、集成、候选及交付门槛。

必须覆盖：错误分类、持久动作/outbox、检查点对账、租约隔离、模型/工具取消与超时、结果补记、开发续接、并行部分完成、Git 集成对账、质量与交付恢复、暂停后切换模型及前端处理入口。

原默认 30 次模型调用、3600 活动秒、2 个执行槽、项目隔离、不可变审批和候选验收不变。贪吃蛇原运行已 30/30，保持暂停；设计与测试不自动提高额度、不自动批准其文档、不替换其历史。既有 45 次特例不扩展到其他运行。

正式 SSE、注册/团队、业务后端部署、任意仓库导入及交付后需求变更不纳入 M2；事件查询和分页对账须支持恢复，实时 SSE 留 M4。七类 Agent 的职责及真实 LangChain/LangGraph 接入保留。

## 3. 必须维持的不变量

1. 每个运行最多一个有效协调租约；租约用 owner + 单调递增 epoch 识别。所有新工具、模型、集成、状态提交都核验 epoch 与有效期。
2. 数据库领取成功后也不得越过旧进程核对；旧执行尚活跃或结果不明时不派发新工具。
3. 每个动作有稳定 operation_id、request_hash、输入基线和执行身份；同键不同参数拒绝，同键同参数返回原动作。
4. 副作用不靠图自动重试。unknown 只有经可验证回执对账才能解除，不把“没找到容器”当成“没执行”。
5. 模型请求发送前原子计量；超时、断线、崩溃均不退还已记调用。新尝试继续消耗同一运行预算及已有任务上限。
6. 工作区、提交、批准文档、计划、候选、测试资产和镜像都有版本/摘要；对账通过不等于业务验收通过。
7. 取消与暂停、切换、恢复同时到达时，取消优先。终态不可改回 running；恢复请求不得清空失败历史。
8. 新执行引用 parent_execution_id 和 recovery_action_id。旧成功执行不改成未完成，旧未知执行不伪装失败。
9. 动作结果、恢复结论、运行状态和后续 WorkItem 同一数据库事务提交；PostgresSaver 作为另一个持久系统单独核对。
10. 没有足够证据时诚实暂停，并说明缺什么；人工确认不能把未验证测试改成 passed。

## 4. 模块和持久数据

沿用 PostgreSQL、SQLAlchemy、Alembic、PostgresSaver，不另加 Redis 或角色常驻服务。

| recovery_service.py / RecoveryAction | run_id、action_key、request_hash、expected_epoch、checkpoint_id、基线引用、状态、输入清单/摘要、结果与阻塞项 |

| lease_service.py | 领取、心跳、活动时间结算、fencing、过期隔离及停止请求 |

迁移先新增可空列/新表、回填可证明关联、最后加约束。不能给历史 unknown 伪造操作回执。历史没有独立回执的动作展示“证据不足”，继续走原有限恢复或保持暂停。迁移必须在专用测试 schema 验证升级与兼容，应用库部署前备份；原审批、交付 SHA/ZIP 摘要不可变化。

恢复动作生命周期：queued → inspecting → ready / blocked → applying → succeeded / failed / cancelled。检查结果 ready 是带过期条件的快照；执行时重新锁定核验，不因早先检查通过便跳过新状态。

## 5. 故障分类与重试

| 分类 | 示例 | 处理 |
| --- | --- | --- |
| 预算保护 | 调用/活动时长/工具/归档上限 | 明确告知耗尽对象与用量；不自动扩额，不绕路建任务 |
| 控制停止 | 用户暂停/取消、租约失效 | 停止新派发、核对活动操作；取消不进入业务修复 |
| 临时模型故障 | 网络、超时、429、5xx | 保留调用计量及结果不确定标识；允许有限新尝试，不保证原调用未计费 |
| 模型配置/协议 | 认证、权限、参数、能力/结构不符 | 提示修配置或受控切换；不自动关思考、换供应商或降级结构校验 |
| 已知命令失败 | 退出码非零、完整输出与快照可核对 | 给 Agent 真实结果继续分析；重跑写操作必须是新显式工具调用 |
| 副作用未知 | 命令未登记、缺回执、Git状态歧义 | 暂停、执行对账；无法证明则人工处理，禁止盲重试 |
| 产品缺陷 | QA断言失败、审查阻断 | 沿用 Supervisor 源码修复/新候选流程，不能用基础设施恢复洗掉缺陷 |

默认保留现行“不自动重试模型网络/协议错误”的策略，M2 提供显式有限重试与安全续接，不偷偷增加付费请求。schema纠正沿用现有一次上限并单独计量。若以后启用自动重试，需另行明确次数和退避策略，不能混入此次设计实施。

错误码只从平台已定义允许名单映射，任意 str(exc)、响应头、请求体、URL凭据和栈中局部变量不返回前端。未知异常保留类型和诊断ID，详情只显示脱敏且可定位的事件关联。预算与控制错误优先于兜底类型名。

## 6. 正常暂停、取消与租约失效

用户请求暂停：保存目的并设置派发栅栏 → 阻止新模型/工具/批次 → 请求停止或等待当前操作在原超时内结束 → 回执对账 → 已确认静止才 paused。前端可显示“正在停止，等待核对”，不提前写“已安全暂停”。

取消：请求事务置 cancelling、取消未领取工作和待审批项、记录事件 → 通知模型客户端停止接收并关闭连接（不承诺供应商不计费）→ 终止已登记的本任务容器/进程并复查 → 标记未完成任务/尝试为 cancelled 或 unknown → 无活动进程后 cancelled，保留未知副作用账本和历史。清理失败保持 cancelling 并显示阻塞项，不能因 owner 为空直接终态。

租约到期：运行锁内提高 epoch、停止新动作、结算上一次活动区间一次、旧 WorkItem unknown → 查询登记进程并停止/核对 → 创建恢复检查动作。检查动作不运行业务代码；失效 Worker 即使拿到旧模型结果也不能登记有效执行。旧 epoch 可以留下隔离回执供新协调者核对，不能直接修改业务成功状态。

Docker 资源槽在容器核实停止后释放；DB advisory lock 断连不等于旧容器停止，必须联合登记表和实际进程核对系统槽。数据库不可达时执行端以本地持久租约截止时间停止，不无限等待数据库恢复。

## 7. 控制端回执与副作用恢复

写入顺序：业务意图提交 → 注册容器和操作 → 执行 → 获取结果/快照 → 控制端暂存文件 fsync + 原子替换并计算摘要 → 业务结果登记 → 受控清理。回执/快照按 project/run/execution/operation 隔离；只读日志截断必须有标志。

回执来自受信控制端，不挂给业务容器写；容器只通过现有受限传输通道返回数据。内容寻址快照不能单独证明它属于哪个动作，回执还须绑定输入hash、epoch、固定镜像、退出状态与操作ID。回执文件缺失或摘要不符时 unknown，不能猜测最后一个 tar 为正确结果。

| 崩溃窗口 | 恢复结论 |
| --- | --- |
| 意图后、确认未启动前 | 仅当启动登记可证未发生且无活动实例时可执行该意图；否则 unknown |
| 命令仍运行 | 有效租约监控；失效租约终止并核实，不先发新命令 |
| 命令结束、回执已保存、业务未更新 | 校验全部身份/摘要后仅补记，不重执行 |
| 命令执行过但无可信回执 | 保留 unknown；即使容器已无也不能自动重做 |
| Git 合并后、业务未登记 | 核对 journal 操作ID、可信控制仓库快照、base/target、双方祖先、构建结果；仅补记 |
| 合并冲突 | 保留冲突路径/双方SHA/快照，走原冲突解决任务；不能以恢复当成已合并 |
| 构建或质量资产完成、DB未登记 | 验证候选SHA/资产/镜像/报告摘要，补记现成证据；无证据的新验证作为新尝试 |
| ZIP生成、交付未登记 | 校验manifest、所有内容摘要及完整gate；复用/登记已有包，不重跑Agent |

工具重复请求仍执行既有 request_hash 合同。磁盘写满、临时文件、回执损坏、镜像变化、路径穿越、他项目回执和未知容器均需负面测试。恢复控制操作也走资源准入和受控路径，不扩大业务权限。

## 8. 工作流与审批对账

每次领取动作先读取业务状态与同 thread_id 的 checkpoint_id、values、next、interrupt，而不是无条件 graph.invoke({run_id})。动作包含预期检查点，状态已前进则返回已有结果/明确过期。

审批决定 + WorkItem 沿用同事务；同版本同决定返回已有项，不新增投递。审批决定保存但图检查点未稳定时保留动作待核对，不能吞掉决定，也不重复创建文档。审批内容、版本、摘要、run_id 与中断不符拒绝。已取消/被替代审批不得恢复运行。

模型已返回但文档未保存：有已验证且版本绑定的结构结果回执可幂等登记；没有结果时新调用继续计费。文档版本唯一键外，还需绑定生成 operation_id，防止节点重入重复生成内容或错误复用不同意见。

并行批次按 execution_id 独立对账：已验证成功分支不重跑；未完成分支在静止与预算检查后新建尝试；仍有 unknown 时所有依赖和集成继续阻断。reducer 保留现有相同身份结果冲突检查，不复用位置式子图检查点。

开发续接不由平台凭 Git 提交推断 completed。收集当前快照、真实check回执、工具结果、旧模型调用记录和批准任务，交给续接执行确认最终结构结果，仍验证提交/范围/检查引用。收尾模型调用也计费；30/30时只允许免费对账和展示，不允许暗中补调用。

## 9. 暂停后切换模型

入口是运行级显式 SwitchRequest，普通修改全局/项目绑定只影响后续新执行，不改活动快照。

流程：选择具体角色/目标 profile revision → 核验目标当前能力指纹 → 请求安全暂停 → 对账活动工具/模型 → 生成无供应商专有消息的中立摘要 → 新 TaskExecution(attempt+1,parent_execution_id) 固定新配置 → 原运行、任务总预算和累计步数继续 → 记录实际生效事件。

中立摘要包含批准文档/任务/依赖、当前提交与快照、已执行动作回执、真实检查、未完成目标；不复制旧模型推理字段、密钥或将模型自述当证据。切换时重新检查配置未被编辑、计划未过期、候选未换，拒绝未验证目标或重复冲突请求。

只有配置切换不改变产品需求，不重新审批原文档；改变文档/任务边界仍走新版本审批。切换不自动处理 unknown、不提高预算；耗尽时返回“可保存切换请求，但当前预算不足以继续”，不显示可成功续跑。

## 10. API 与前端交互设计

接口为设计合同，R1/R2已上线部分见docs/28，通用resume/模型切换仍未上线；版本校验、幂等键和 run/动作归属需由代码统一检查。

| 接口 | 行为 |
| --- | --- |
| GET /runs/{id}/diagnostics | 当前失败、用量、活动操作、最近检查点、可执行动作及禁止原因；只读 |
| POST /runs/{id}/pause | 幂等保存暂停请求，返回请求ID及状态，不承诺立即静止 |
| POST /runs/{id}/recovery-checks | 创建只核对不调用模型的持久动作，返回action_id |
| GET /recovery-actions/{id} | 展示核对进展、证据和阻塞项 |
| POST /runs/{id}/resume | expected_recovery_id/epoch/checkpoint + 幂等键；锁内重验后原子投递 |
| POST /runs/{id}/model-switches | 固定角色、目标revision、原执行及暂停意图，显示成本影响 |
| GET /runs/{id}/model-switches | 查询请求、实际生效与新旧执行关联 |
| POST /runs/{id}/cancel | 保留路径，修正生命周期；重复请求不重复杀进程 |
| 事件分页 | 可按run和稳定(created_at,id)游标查询历史，不依赖最近100条 |

右侧面板显示：具体原因 → 停在哪个阶段/动作 → 已保留成果 → 是否有未知结果 → 下一步。操作按钮由后端诊断返回的许可状态决定，点击时后端仍再验证。技术详情保留错误码/诊断ID，不向普通用户暴露大量原始JSON。

按钮区分“核对执行结果”（不调用模型）与“继续执行”（可能付费）。预算耗尽展示数字和阻塞项；无预算调整授权时不出现自动扩额。原历史成果、版本审批、取消和已有有限恢复入口保留。刷新后展示同一恢复动作，不能因页面重载重复POST。
