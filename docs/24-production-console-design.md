# B方案：生产控制台实施

后续组件升级：用户再次选择 B「光路编排」，保留本页布局与行为，组件色板、质感与动效以 [docs/25](25-lightpath-components.md) 为最新视觉决定。

用户选择已生成的B效果图，授权按图落地。保持业务范围、审批、预算与隔离规则不变；仅实现前端体验，不宣称正式M4/SSE或完整M2完成。

设计基线：石墨底#24282A、面板#303638、分隔#444B4C、正文#E6E2D9、琥珀#C48A58、成功绿#8EA792。标题Segoe UI/微软雅黑，正文同系统中文无衬线，时间/任务ID使用Consolas；避免外部字体网络依赖。以真实任务依赖画布作为识别元素，窄工具栏、横向项目栏、右侧当前操作与底部记录共同构成控制台。原图中错误方向的装饰连线不照搬，实际箭头必须按真实依赖由上游指向下游。

## 实施结果

- 已替换整套前端视觉：统一石墨背景、铜琥珀操作色、柔和绿色完成状态、窄SVG图标工具栏、顶部项目选择/预算/新建入口、横向项目切换栏、右侧运行控制与底部简明记录。项目栏状态从真实运行查询，切换后自动在横向列表内露出选中项目；不会滚动整个页面。模型配置、原五分类、历史运行、版本审批、已知暂停修正、质量修订与交付均保留。
- `WorkflowCanvas.tsx`从所选运行的文档/当前计划/协作记录/候选/报告/交付构建画布。架构草案明确“尚未派发”，图不创建任务。依赖箭头由depends_on生成，多个任务按拓扑关系排列；分支/汇合均保留。执行成功与已集成区分，冲突/unknown与暂停的运行中任务不冒充完成；QA/终审按候选ID、SHA和最新尝试绑定，不挪用旧候选或旧SHA的通过结果。
- 节点跳转到对应分类，交付节点定位真实交付卡；缩放/适应按钮实际可用。没有数据时显示未生成/尚无报告。手机采用同一数据的纵向依赖列表，保留中文说明；键盘焦点、原生可访问标签、缩放按钮禁用边界与减少动态效果偏好保留。
- 原图的右侧“当前需要你处理”根据真实待审批项出现，仅提供进入正文的操作；没有复制一个绕过正文的新审批接口。其余状态显示运行控制/暂停原因。所有数据读取仍使用已有API，未修改后端、数据库、预算、审批或业务项目源码。此改造不等于正式M4事件/SSE或M2恢复完成。

1. `npm run build`通过TypeScript与Vite生产构建；最终JS约436.70kB、gzip136.49kB。
2. 全套Playwright **42 passed，49.8秒，0失败/错误/跳过**。`.local/production-console-tests.xml`及日志。包含原36项审批/暂停/文档/模型/交付/分类回归，以及新增6个桌面手机图形合同场景：真实夹具依赖箭头、节点导航、缩放/适应、移动依赖、草案不当执行、不意外审批、不继承不同候选ID或不同SHA的旧QA通过结果。测试HTTP夹具明确标注，真实控制面加载检查保留。
3. `node scripts/production-console-live.mjs`：4组历史真实模型交付加当前贪吃蛇，5项目×1440/390，共**10个真实Edge/HTTP上下文通过**。实际项目选择/历史轮次、选中项目可见、五分类、缩放、文档列表、模型设置密钥空白/密码类型、无页面错误或页面横向溢出、无POST/写请求。报告`.local/production-console/live-results.json`，概览/文档/模型截图同目录，已目视检查桌面、手机和模型设置。
4. `node scripts/organization-live.mjs`：最终界面再次对4组已交付运行×桌面手机，共**8个真实上下文**核对QA/Reviewer ID、真实下载ZIP摘要、打开正确预览、事件默认折叠与历史查询，全部通过。报告`.local/workbench-organization/live-results.json`。这8个上下文与上述10个有重叠，不能算18个不同项目。

本轮未调用模型API、未启动或批准运行、未提高任何预算。检查时贪吃蛇已有自己的暂停状态和30/30用量，页面如实展示，本次设计不改变该业务状态。后端/业务代码未改，未重新运行后端测试或重新生成业务项目，不把旧里程碑结果冒充本轮全量验证。
