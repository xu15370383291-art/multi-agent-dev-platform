### 并行回归发现与锁顺序修复

原完整回归在真实双任务集成用例发生PostgreSQL deadlock。专项复现保留于`parallel-retest.log`，确认并非“任务未同时运行”的弱化断言问题：无执行控制上下文的`agent.started`日志先锁事件head，随后Event外键隐式获取Run KEY SHARE；另一事务先持Run锁后等待head，形成循环。

修复将所有Event发布入口统一为Run ID排序取得运行锁、验证归属，再取得项目head；仍由同一业务事务提交。旧epoch执行护栏仍先执行。新增`test_unscoped_event_writer_locks_run_before_event_head`在运行被另一事务锁住时验证事件写方不能提前占head，并保留原真实并行用例全部断言。旧全量运行已在无业务Docker容器的窗口停止并记为未通过/被替代，不复用其部分结果冒充全量通过。原始日志与中断记录保留。
