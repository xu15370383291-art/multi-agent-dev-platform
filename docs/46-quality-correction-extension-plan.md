## 现有边界

`repair.defects`对“未完成有效断言就报错”的混合失败整体暂停，防止把错误测试误当源码缺陷。`quality_revision.validate_revision`仅允许少数已识别的脚本语法/API错误；错误测试断言按用户已批准的人工核对协议处理。本轮docs/44明确保留该边界。因此扩大自动分流/测试修订审批范围须用户确认，不能直接用新策略或重试绕过。

## 建议批准的扩展

1. 增加持久、版本绑定的质量诊断工作：主管对照批准AC、固定源码、原脚本、真实失败和工具合同分类，不能改批准需求或用模型自述覆盖回执。
2. 对可由调用签名与实参确定的测试API误用，生成最小调用修订；不允许删除/跳过/放宽原断言。保存旧新脚本、摘要、证据和修订关联，由独立Reviewer核对修订是否确实只改变调用方式。
3. 对漏掉的原要求只新增更完整的测试，保留原检查；持续时长等要求须真实执行并留下控制端观测，不能拿快速模拟代替。
4. 源码缺陷独立形成Developer修复任务、真实检查与新候选。混合失败不能再导致所有来源混为一谈，但未核实的失败不能随意归入某类。
5. 修订后在新候选完整执行原全部AC、既有回归与新增检查，再由独立Reviewer审查；任一阶段不通过都不能交付。没有新有效证据时停止重复尝试，计数与失败历史不清空。
6. 更改正确/错误的业务断言、调整验收语义或批准要求、凭据/审批、未知工具结果、无法确定错误来源等仍须人工决定，不纳入自动放宽。

## 批准后的实现与测试

- 模块：版本化质量诊断/修订合同与工作项，原repair/quality_revision/QA/Reviewer接线，实际时长证据的版本化QA镜像，简单原因及处理进度。
- 隔离测试：正确来源/错误归因拒绝、最小API修订、断言未改/未弱化、漏测补齐、旧版本及计数保留、重启、重复/空转、取消/失租、unknown禁止重放、候选SHA与镜像绑定、最终独立审查。
- 真实测试继续原推方块这一项目，不增加收费项目；实测五分钟及最终预览/ZIP核对。方案未批准前不改原质量门槛。
