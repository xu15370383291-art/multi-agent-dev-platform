## 建议增加的受控权限

在已有API修订上，允许自动修正**测试前置操作、等待条件、辅助导航循环、参数及断言的执行环境**，前提是批准需求与实际源码/执行回执能证明测试步骤错误，且不改变任何原业务断言的表达式、期望值、阈值或原AC。本次只处理上表明确的操作步骤错误；整数宽度等可能涉及断言解释的问题不自动放宽。

控制端生成原/新脚本差异及摘要，静态核对原全部断言的AST文本按序保留、全部原AC保留、未新增跳过/异常吞噬/假通过/替代生产算法；新增断言可以更完整，但不能替换原检查。修订模型与独立Reviewer分别对照批准需求、原脚本、真实失败、固定源码；结论不一致仍要求人工，不用多数表决豁免质量门槛。

业务要求、正确断言的含义/期待值、审批、隔离、未知副作用等仍不自动修改。源码缺陷必须由Developer修复、新SHA/候选、真实检查；测试修订不准改源码来迎合错误步骤，不准把未执行视为通过。旧脚本、旧失败、消耗、结构化诊断和拒绝全部保留，原运行继续。
