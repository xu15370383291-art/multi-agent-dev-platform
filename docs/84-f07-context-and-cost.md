### 新片段绑定及旧片段兼容

`coverage_review`在新片段保存完整证据指纹、候选身份、批准文档ID；指纹覆盖全量源码文件、批准需求/架构、测试资产、真实执行、来源与AC范围。恢复重用前逐项匹配；`coverage_claim_audit.valid`在交付门禁同样重算新绑定。仅换提示文案、记录ID或测量元数据不算新的执行证据；内容/版本变更不能借旧结论通过。

旧片段按原密封回执保留，并以原候选、任务的批准文档关联、实际QA完整脚本/执行、完整派生文件目录交叉核对。旧协议没有新字段，不回填或覆写为新验收；它依赖原文档和候选不可原地改写的既有规则。改范围须新版本/批准。原15份实际片段重复只读校验均可复用，改变候选SHA、测试资产、批准需求/架构、脚本或执行的6类反例均被拒。证据 `.local/f07-original-reuse.json`，0模型调用、原终审payload不变。

测试中的新密封片段第一次生成后再次进入0新增回调；批准或执行变化拒绝复用。原始结果哈希继续验真，缓存命中不新增Invocation、不把命中当付费调用。

### 后续请求可量测与查询

新增 `request_metrics.py`，结构化模型请求在原预算/调用意图事务中保存数值量测；Developer记录实际压缩后的LangChain消息/工具快照大小。成功和失败均保留可取得的适配器耗时；结构校验异常中若已有可信供应商usage则保留，未取得仍缺失，不能计零。

记录：应用JSON UTF-8字节、schema大小、精确相同字符串值的重复字节、请求类别（逐AC/纠正/审核/生成/开发等）、adapter_elapsed_ms。结构化请求的human_json是实际HumanMessage内容的JSON大小；Developer是消息/工具快照大小，均不是HTTP线包或计费tokenizer。适配器耗时含SDK、供应商等待及解析，不能宣称单独测到网络等待。进程被中断且没有完成计时的字段保持缺失。

量测只存数字和白名单合同标签，不复制请求正文、源码、推理内容、凭据、异常原文；仅在Invocation原JSON usage增加metadata，无数据库迁移。`api`协作详情的invocations新增经过白名单过滤的usage/request_metrics；老记录显示空量测，不追记虚假历史。只读查询入口：

```powershell
# 在backend目录执行，不调用模型、不读密钥
.\.venv\Scripts\python.exe -m scripts.measure_requests --run-id <运行ID>
```

实际正式旧运行查询保存 `.local/f07-request-costs.json`：86次、4次usage未知、历史请求量测缺失。生产API核对字段已上线，不因缺历史量测把旧请求当零输入/零耗时。

另移除 `quality_generation.verified_chunks` 中残留的“最多30项”进展识别过滤。它原先没有限制实际生成，但超过30项的有效生成回执不被识别为进展，可能导致额外核对。40项显式回执反例现可识别；生成进展仍不是测试执行通过，原旧v1单例协议和所有审批、预算/循环/取消/隔离规则保留。
